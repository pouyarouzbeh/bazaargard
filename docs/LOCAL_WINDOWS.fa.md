# اجرای لوکال بازارگرد در ویندوز

مسیر این کپی: `C:\Users\Public\Documents\torob`

## نصب وابستگی‌ها (برای نصب مجدد)

در PowerShell، از پوشهٔ پروژه:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
npm.cmd --prefix frontend ci --no-audit --no-fund
npm.cmd --prefix frontend run build
```

Python 3.12 یا بالاتر و Node 20.19 یا بالاتر لازم است. نیازی به فعال‌سازی محیط مجازی یا نصب Docker و Make نیست. وابستگی‌های ویندوز شامل داده‌های منطقهٔ زمانی تهران و خواندن فایل `.env` هستند.

## دیتاست و اجرا

اگر دیتاست CSV دارید، ابتدا فایل فشرده را استخراج کنید. مسیر پوشه‌ای را بدهید که هر سه فایل `products.csv`، `shops.csv` و `offers.csv` مستقیماً در آن هستند:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-local.ps1 -DatasetDir "C:\path\to\csvs"
```

این دستور کاتالوگ را می‌سازد و برنامه را اجرا می‌کند. کاتالوگ موجود بازنویسی نمی‌شود. اگر فایل آمادهٔ `catalog.db` دارید، آن را در `data\catalog.db` قرار دهید.

برای دفعات بعد:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-local.ps1
```

سپس نشانی <http://127.0.0.1:8506> را باز کنید. توقف با `Ctrl+C` است. گزینهٔ `-Port 8507` پورت را عوض می‌کند. رابط API در <http://127.0.0.1:8506/api/docs> و وضعیت آماده‌بودن در <http://127.0.0.1:8506/api/ready> است.

## تنظیم مدل

در کلون تازه، با `Copy-Item .env.example .env` فایل تنظیمات لوکال را بسازید؛ این فایل در Git نادیده گرفته می‌شود. برای گفت‌وگوی مدل، کلید خود را در `BOXAPI_KEYS` وارد کنید؛ مدل‌های پیش‌فرض همان تنظیمات مخزن هستند. برای استفاده از مسیر Anthropic پروژه باید `LLM_PROVIDER=anthropic` و مقادیر واقعی `RELAY_URL` و `RELAY_TOKEN` تنظیم شوند. توکن‌ها را در فایل لوکال بنویسید.

بدون کلید مدل، جست‌وجو و امکانات کاتالوگ کار می‌کنند، اما پاسخ‌گویی مدل فعال نیست. بدون دیتاست، رابط خرید قابل استفاده نیست و لانچر خطای مشخص نمایش می‌دهد.

## توسعه با به‌روزرسانی خودکار

برای بک‌اند از `-Reload` استفاده کنید و در یک ترمینال دیگر فرانت‌اند را اجرا کنید:

```powershell
npm.cmd --prefix frontend run dev -- --host 127.0.0.1
```

Vite نشانی رابط را چاپ می‌کند و درخواست‌های `/api` را به پورت `8506` می‌فرستد؛ در این حالت بک‌اند را روی پورت پیش‌فرض نگه دارید.

## تست‌ها

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q tests
```

برای تست‌های دیتاست واقعی، قبل از دستور بالا مسیر `TEST_CATALOG` را تنظیم کنید:

```powershell
$env:TEST_CATALOG = (Resolve-Path .\data\catalog.db).Path
```

## نتیجهٔ آماده‌سازی این سیستم

وابستگی‌ها نصب شدند، فرانت‌اند بیلد شد و کاتالوگ `data/catalog.db` با ۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ پیشنهاد و ۶٬۴۷۶ فروشگاه ساخته شد. بررسی `SQLite quick_check` موفق بود. صفحهٔ اصلی، `/api/bootstrap`، `/api/ready` و جست‌وجوی واقعی پاسخ موفق دادند.

از ۴۰۳ تست مخزن، ۴۰۰ تست موفق و ۳ تست ناموفق بودند. محدودیت‌های فعلی اجرای مستقیم روی ویندوز:

- تست استخراج متن PDF در `tests/test_guard.py` به ماژول `resource` وابسته است که در ویندوز وجود ندارد؛ استخراج PDF منابع وب در این محیط قابل اتکا نیست.
- دو تست آزمایشگاه جانبی Ops در `tests/test_ops.py` ناموفق‌اند. فرآیند آزمایشگاه با محیط حداقلی ساخته می‌شود و در این سیستم با `WinError 10106` هنگام ایجاد سوکت متوقف می‌شود. این بخش از اجرای اصلی دستیار خرید جداست.

گفت‌وگوی مدل تا زمان واردکردن کلید API در `.env` فعال نیست. پس از تغییر `.env`، بک‌اند را متوقف و دوباره اجرا کنید.
